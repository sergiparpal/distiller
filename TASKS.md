## Known limits

Limits kept as they are: decided so, or reached only with values that no real run gives.
- **Note 9.** `junit.parse_junit` takes every `testcase` element as a test case, at any depth and under any root, so a well-formed file with none, such as `<html><body/></html>`, gives no results and is not rejected; and it looks for `failure`, `error` and `skipped` only among a test case's own children, so a `failure` inside its `properties` fails nothing (run with defusedxml 0.7.1 on Python 3.12.3, 2026-10-18). pytest 9.1.1's `to_xml` writes them as the test case's children, under `testsuites` and `testsuite`. No test pins either. Open question 7 keeps the first as a known limit, which Rule 5 lists (2026-10-27).
- **Note 11.** A `time` that matches Rule 5's pattern but rounds to 10^25 s or more makes `Decimal.quantize` raise `decimal.InvalidOperation`, since the default context keeps 28 digits: `9999999999999999999999999.9994` gives 9999999999999999999999999999 ms, and `9999999999999999999999999.9995` raises (run with Python 3.12.3, 2026-10-18). That is no `Rejected`, so the run ends as an unexpected failure, exit 1 with no record, although by the SPEC the test case can be used. No test pins it. Open question 7 keeps it as a known limit, which Rule 5 lists (2026-10-27).
- **Note 12.** `parse_junit` turns only Rule 5's three exceptions into rejections, and raises each `from None`, so that no traceback shows the parser's error, whose text can quote the file. An XML declaration naming an encoding that Python lacks makes `fromstring` raise `LookupError`, and one naming a multi-byte encoding that expat lacks, such as `shift_jis`, `ValueError`, both from pyexpat's handler for unknown encodings (run with defusedxml 0.7.1 on Python 3.12.3, 2026-10-18). Neither is a `Rejected`, so the run ends as an unexpected failure, exit 1 with no record. Whether such a file is "not well-formed XML", and so `unusable-input`, is the SPEC's to say; no test pins it. Open question 7 keeps both as known limits, which Rule 5 lists (2026-10-27).
- **Note 13.** A file whose internal subset refers to an undeclared parameter entity before it declares an entity, as `<!DOCTYPE testsuites [%pe;<!ENTITY unused "never used">]>` does, is not `unsafe-xml`: without `standalone="yes"`, expat skips the entity declarations after such a reference, defusedxml is never told of them and raises nothing, and the file parses (run with defusedxml 0.7.1 on Python 3.12.3, 2026-10-18). Nothing is resolved or expanded: a reference to that entity in content raises `ParseError`, so `unusable-input`, and one in an attribute is dropped, so `classname="&module;"` reads as `""`. There the SPEC's "declares an entity, even one it never uses" and Rule 5's defaults disagree; no test pins it. Open question 7 keeps it as a known limit: Rule 5 says that such a declaration does not make the file `unsafe-xml` (2026-10-27).
- **Note 26.** `matches` tries, for each `*`, every number of characters it could take, and for each `**` that does not end the pattern, every number of segments, so its time grows as a power of the number of wildcards in one pattern. The default patterns, `data/**` and `db/*.sql` against 2,000 changed paths of six segments, none of which they match, take 0.05 s; against a name of 255 `a`, which it does not match, the segment `*a*a*b` takes 0.34 s and `*a*a*a*b` 22 s, and `**/**/**/**/x` against a path of 100 segments takes 1.1 s (run with Python 3.12.3, 2026-10-20). Decided, 2026-10-20: a known limit, with no cycle of its own. If a real configuration needs it, the linear algorithm stays an option: each piece between two `*`, and each run of segments between two `**`, taken as early as it can be, so that the time no longer grows as a power of the number of wildcards. It adds a branch, for a piece that is not there, that no test reaches, so it would need a tests phase first. No test pins the time.
- **Note 30.** In a test's `name`, pytest writes each character that XML does not allow, and DEL, as `#x` and its code (`bin_xml_escape`), which the pair rule does not do. By default pytest has already turned such characters in parametrize ids into backslash escapes, in the node id too, so none is left for `bin_xml_escape`; only with the ini option `disable_test_id_escaping_and_forfeit_all_rights_to_community_support` would such a test count as unmeasured, and so be selected. - **Note 46.** A `--pr` of more than 4,300 digits is ASCII digits above 0, so no usage error by the SPEC, but Python's default limit on converting between `int` and `str` keeps `int()` from reading it, and `json.loads` from reading such a `pr` in a line. No test pins what the command line does with one. Task 11's test of a `pr` of 4,301 digits assumes that default: with `PYTHONINTMAXSTRDIGITS=0`, which lifts it, that line would be a record.

Opening with `O_NONBLOCK` and then checking with `os.fstat`, instead of Rule 3's `os.stat` first, would not block: a FIFO opened that way for reading opens at once, and one opened for writing with no reader fails with `ENXIO` (checked on Linux, 2026-10-25). Found in task 12's tests phase, 2026-10-25. Decided on 2026-11-15 in 00e2aab, as the user chose: Rule 3 lists it as a known limit, kept as it is; opening with `O_NONBLOCK` stays an option.
- **Note 73.** The savings' `Decimal` division rounds to the default context's 28 significant digits before `quantize` rounds to one decimal, so a quotient just short of a tie can round up.
